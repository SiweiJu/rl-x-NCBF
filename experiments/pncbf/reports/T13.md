### Model details (all switches; defaults in brackets)
- Input: (x⁺ without base_xy/base_yaw, ũ, ξ) normalized; `use_xi` [on]. Output: normalized delta over all dims except
  `last_action`. `last_action` of x̂⁻_{t+1} is set to the chosen undelayed u_t (`last_action_source=chosen`; matches
  the env's previous-action obs; `applied` / `predict` available).
- base_xy / base_yaw: never an input (translation/yaw invariance); their delta is predicted in the heading frame of
  x_t and rotated, yaw wrapped. So the world-frame (wm-data) and window-frame conventions both work.
- Loss: mean over windows, k_train steps and predicted dims of ((x̂⁻ − x⁻)/σ_Δ)², σ_Δ = per-dim std of the one-step
  delta (floor 1e-3). **Method A** [default]: at a step with `perturbed_next | dr_resampled_next`, continue from the
  recorded x⁺ (teacher forcing). **Method B** (`--method B`): windows with a shock between two of their steps are
  masked. Ensemble members each roll out on their own predictions; losses are summed.
- Optimizer: Adam 2e-4, global clip 1.0, batch 4096 windows, neg (near-failure) share 0.3, 50 updates per jit call.
- `rollout(wm, bundle, x0, xi, delay_buffer0, u0, policy_fn, H, delay_step_fn, open_loop)`: u0 goes through
  `delay_step` at t, then u_j = policy_fn(x̂_j); returns x̂_{t+1..t+H} (H, N, S). Closed loop [default]: ∇_{u0} also
  flows through the policy's reaction; `open_loop=True` stops the gradient at the policy outputs (same values).
  With wm-data: `delay_step_fn = lambda b, u: wm_state.delay_step(b, u, wm_state.delay_steps_from_xi(xi_full, xl))`,
  `policy_fn = lambda x: policy(full_obs_fn(x, command, xi_full))`, WM ξ = `xi_full[..., meta["schema"]["xi_active"]]`.

### Data (wm-data schema `pncbf-p1-wmdata/v1`)
- Split from `meta.json` `split` (test = seeds 145/245, ppo 1342/1442); without it, `--heldout_pattern`.
- Compact in memory: x⁺_{t+1} = x_plus[t+1] inside a window (not loaded); x⁻_{t+1} stored only where it differs from
  x_plus[t+1] (shock / DR / done rows; the loader checks every row and stores all mismatches); ξ = xi_table[xi_idx],
  only the dims that vary on the training data (`xi_active`, saved in the bundle).
- Windows starting at `episode_step == 0` are masked (stale IMU values after a reset).
- Logged checks: last_action(x⁻_{t+1}) == u_cmd_t; rows where x⁻_{t+1} ≠ x⁺ of the next row outside shock/done rows.

### Per env step (decision point A: shield ≤ 3× one PPO env step)
PPO env step = T06b policy + env step in the rollout scan: **4.24 ms** (job 182814; 4.06 ms on a 3090), with the
critic shield (ii_h25) 4.95 ms. WM rollout + VJP w.r.t. u0 (job 182839 @ 954d9f0), ms:

| config | H=10 | H=16 | H=25 | H=25 / 4.24 ms |
|---|---|---|---|---|
| full VJP, f32 | 6.3 | 9.9 | 15.1 | 3.6× |
| full VJP, bf16 matmuls (f32 acc) | 5.8 | 9.4 | 14.1 | 3.3× |
| **gated VJP 25 %**, f32 | 4.8 | 7.7 | 12.0 | 2.8× |
| **gated VJP 25 %**, bf16 matmuls | 4.5 | 7.1 | 10.5 | **2.5×** |
| gated VJP 50 %, f32 | 5.8 | 9.3 | 14.7 | 3.5× |
| gated VJP 50 %, bf16 matmuls | 5.5 | 8.8 | 12.9 | 3.0× |
| forward rollout only (no VJP), f32 | 1.9 | 2.9 | 4.5 | 1.1× |
| open loop full VJP, f32 / bf16 mm | 5.4 / 4.9 | 8.4 / 7.8 | 13.3 / 12.0 | 3.1× / 2.8× |
| 256×3 full VJP f32 / gated 25 % | 4.3 / 4.1 | 7.0 / 6.4 | 10.9 / 10.0 | 2.6× / 2.4× |
| 512×4 full / gated 25 %, bf16 mm | 6.9 / 5.1 | 11.1 / 8.2 | 17.5 / 11.6 | 4.1× / 2.7× |
| 1024×3 full / gated 25 %, bf16 mm | 9.6 / 6.2 | 15.3 / 9.9 | 24.1 / 14.9 | 5.7× / 3.5× |
| ensemble 5 full / gated 25 %, bf16 mm | 18.5 / 10.3 | 30.0 / 16.7 | 47.4 / 25.6 | 11× / 6.0× |

- The gated VJP does not scale with k: the VJP of 256 envs costs ~7.5 ms vs ~10.6 ms for 1024 (latency-bound small
  matmuls in a 25-step scan), so 25 % saves ~20 %, 50 % almost nothing.
- bf16 matmuls with f32 accumulation save only 5–12 % (same reason). Casting everything to bf16 (job 182813) was 11.8 ms.
- Same numbers with wm-data's real `policy_obs_from_state` / `margin_fall` (182814): 15.2 ms full VJP.

### Per training iteration (the ratio GB uses; job 182833 @ 14005c1, A5000)
Real T06b training (1024 envs × 128 steps, 10 epochs, critic trained in all runs), 10 timed iterations each after
one compile iteration (spread < 1.5 %). "PPO + WM" = T06b ppo with the WM rollout + VJP for all envs at every rollout
step (the WM is not inside the anticipation loss). WM training = 50 updates / iteration (plan 4.10) at the measured
20.2 ms / update (batch 4096, k=8; 18.2 ms with bf16 matmuls), added on top.

| run | iteration (s) | + WM training (s) | total vs T06b ppo | vs T06b ii_h25 |
|---|---|---|---|---|
| T06b ppo (no shield) | 2.83 | – | 1.00× | |
| T06b ii_h25 (critic shield) | 3.63 | – | 1.28× | 1.00× |
| PPO + WM full VJP, f32 | 4.82 | +1.01 | 2.06× | 1.61× |
| PPO + WM full VJP, bf16 mm | 4.70 | +0.91 | 1.98× | 1.55× |
| PPO + WM gated 50 %, f32 | 4.57 | +1.01 | 1.97× | 1.54× |
| PPO + WM gated 25 %, f32 | 4.25 | +1.01 | 1.86× | 1.45× |
| **PPO + WM gated 25 %, bf16 mm** | 4.14 | +0.91 | **1.79×** | 1.39× |

The in-loop cost matches the per-step numbers: (4.82 − 2.83) s / 128 steps = 15.5 ms per step. So decision point
B's "training time ≤ 3× PPO" holds with margin for all 512×3 variants; the per-step 3× of decision point A holds only
with the gated VJP (or 256×3, or H ≤ 16). The WM training is ~20 % of a D iteration; fewer updates per iteration
would cut it proportionally.

Footnote (4096 envs, 512×3 f32 H=25): env step + policy 9.3 ms; WM full VJP 48.7 ms (5.2×), gated 25 % 27.4 ms
(2.9×), forward 12.6 ms. The 5-member ensemble runs out of the A5000's 24 GB at H ≥ 16 there.
