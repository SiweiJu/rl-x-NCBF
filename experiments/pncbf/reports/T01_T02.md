## 2. T02: F1 and F2

### What was still broken on `multistep`
- **F1, critic input:** already fixed as a side effect of B2. With `critic_action_index="current"` the critic is
  trained on `(states[t], env_actions[t])`, both recorded *before* `env.step`, so the episode-ending step has its
  real pre-reset input. The paper code read `(env_state.last_state, last_action)` after the step, i.e. `(0, 0)`
  after the auto-reset. New switch to reproduce that: `algorithm.ncbf.terminal_critic_input="zeros"` (also applied
  to replayed negatives). Default `"pre_reset"`.
- **F1, shield first step:** still present. The shield's `h_prev = h(last_state, last_action)` was evaluated on
  the reset input (`(s_0, 0)` on multistep, `(0, 0)` in the paper code). Fix (plan §4.6): on the first step of an
  episode (`info_episode_store["episode_step"] == 0`) `h_prev := gamma_c`, so the constraint is `h_next >= gamma_c`
  (scaled form). Switch `algorithm.ncbf.first_step_prev_value="gamma_c" | "input"` (legacy). The first-step flag
  is passed to the shield in the rollout, the anticipation loss (stored in the transition), the eval rollout and
  `_policy_and_shield`. Checkpoints without the key load with `"input"`.
- **F2:** multistep had already replaced the paper's raw-vs-shielded term by an adjacent-pair term
  (`w_temporal`, default 0), but it also had an extra "unsafe pairs must decrease" term and ignored
  `gamma_c_scaled_by_eta`. Now (`ncbf_targets.temporal_consistency_loss`):
  `ReLU(-(h(s_{t+1},a_{t+1}) - (1-eta) h(s_t,a_t) - eta*gamma_c))` = paper eq. (4) with alpha = eta, on
  safe->safe pairs inside one episode (`successor_pairs`: not across `done`, not at the rollout end, both labels
  unmasked); both actions are `env_actions` (executed, processed scale). Switches:
  `algorithm.ncbf.temporal_mode="adjacent" | "legacy_raw_vs_executed"` (paper code: `h(s_t,a_exec)` vs
  `h(s_t,a_raw)` at the same state, no eta, raw action unprocessed), `algorithm.ncbf.temporal_pairs="safe_safe" |
  "safe_safe_and_unsafe"` (previous multistep term). Weight stays `algorithm.ncbf.w_temporal` (default 0.0 per
  repo convention B4; the paper code used `w_cbf=1.0` -> **set `w_temporal=1.0` for (ii)-fixed runs**).
- Label / target code moved out of `train()` into `ncbf_targets.py` (pure functions, unchanged logic) so it can be
  tested. Observation: `y_t` uses terminations at transitions t..t+H (H+1 transitions) while the min-target uses
  H next states; existing behavior, left unchanged.

## 3. Requeue-safe resume
- Runner: `runner.resume` (False), `runner.save_interval_iterations` (0), `runner.save_interval_minutes` (20),
  `runner.wandb_tags` (comma list). With `resume=True`: `--runner.run_name` must be given explicitly (else error;
  default is a timestamp), run dir `experiments/runs/<project>/<exp>/<run_name>`, wandb
  `id=<run_name>-<sha1(project/exp/run)[:8]>`, `resume="allow"`; wandb config gets `run_info` (git commit of the
  imported rl_x tree, SLURM job id, `SLURM_RESTART_COUNT`) and, on each restore, `resume_history` /
  `resume_nr_restores`. Algorithms without `SUPPORTS_RESUME` refuse `resume=True`.
- PPO (full-jit): after every learning iteration a host callback decides whether a checkpoint is due (iterations
  or minutes, plus the final one). Checkpoint = policy/critic/ncbf/encoder/decoder `TrainState`s (params,
  **optimizer states**, step), env curriculum (`env_curriculum_coeff`, `env_curriculum_levels_in_a_row`), number
  of completed updates, meta. Written atomically: `resume/step_N.partial` -> rename `step_N` -> write
  `LATEST.tmp` + fsync -> `os.replace` to `LATEST` -> delete older steps. A kill at any point leaves `LATEST` on a
  complete checkpoint; `.partial` dirs are ignored. On start it restores `LATEST` (or starts fresh), skips the
  completed updates (the partially done eval/save block is finished first, then the scan continues), so the
  global step, LR/beta schedules and logging continue. `save_model=True` no longer fails on an existing dir.
- Not restored (documented): env state (all envs re-reset, episodes restart), the NCBF negative replay buffer
  (one rollout with the default `neg_buffer_size=1`), the exact RNG stream (re-derived: `fold_in(key, update)`).
  Wandb drops metrics with steps below the last logged step, so the window between the checkpoint and the
  preemption is not re-logged.
- `runner.load_model` (existing): restores params + optimizer states (TrainState) and the algorithm config from a
  `latest.model` zip, but starts at update 0 (step counter, beta schedule, env curriculum start over) and the run
  dir is the new run's. It is a warm start, not a resume.
- **CPU kill test** (`experiments/pncbf/scripts/cpu_resume_test.sh`, 16 envs, 64 updates, checkpoint every 3):
  attempt 1 SIGKILLed right after `LATEST=step_000000003` (it had already logged step 1024 = update 4);
  attempt 2 (same command): `Resume: restored .../step_000000003 (update 3, step 768)`, next logged steps 1024,
  1280, checkpoint at update 6, ..., finished at step 16384 (exit 0). Also a unit test checks the round trip of
  params + optimizer states + counters and that a `.partial` dir is ignored.

**SafeFall (`ncbf-q-safefall`, commit 804c7a5) — small, low risk.**
- Needs: label rule only. In `window_any_done_next_H` (now `ncbf_targets.window_any_done_next_H`):
  `safe = dist > H + 1`, `unsafe = dist <= safe_fall_H`, and samples with `safe_fall_H < dist <= H` are masked
  out (`mask &= ~notdefined`); config `ncbf.safe_fall_H = 5`. Port = optional `safe_fall_H` argument
  (None = current rule) + config key + 1 unit test. Can be done in the pure function without touching `train()`.
- Risks: (a) its `safe` uses `> H + 1` whereas the base rule is `> H` (one-step offset; decide which is
  intended); (b) the same commit also changes the MJX/CPU env observation (full `data.qpos/qvel` instead of the

  identical, for G1 it changes the obs size; do not port that part unless T03 shows the SafeFall runs needed it;
  (c) which H / safe_fall_H the paper runs used must come from T03 configs.

**Version (i) "nominal MJX one-step shield" (`ncbf`, 78d9f1c) — medium, several risks.**
- Needs: `get_dynamics_step_function_mjx(env)` (`flax_full_jit/ncbf.py:326` on `ncbf`): nominal `mjx_model` from
  `env.initial_mj_model`, sets `qpos[3:7+n]`, `qvel` from the observation, `ctrl = u`, `nr_substeps` × `mjx.step`;
  its `make_get_safe_action` with `system_forward_dynamics_function`, `state_from_obs_id =
  env.dynamics_observation_indices` (exists on multistep), `ncbf_obs_in_dynamics_state_id =
  env.ncbf_obs_in_dynamics_state_idx` (exists); `a = jacrev(h(f(x,u)))`, `c = -h(f(x,u0)) + h(x) - eta(h(x) -
  gamma_c) + a^T u0`. The critic there is **state-only** `h(x)`; on multistep it is `h(s, a, z)`. Plan §11 puts
  this behind `safety_value.py` with `source = mjx_nominal_1step`, so the port is: a state-only critic variant
  (or `h(x_{t+1}, a_{t+1}=?)`), the dynamics function, and a residual source switch in the shield; training of a
  state-only critic needs its own label pairing (y_t for h(s_t)).
- Risks: (a) `ctrl = u` bypasses `control_function.process_action` (PD targets, action scaling, delay) — the
  nominal model is fed the wrong control unless the processing is reproduced; (b) base position `qpos[0:3]` is
  not set from the state (template default height) — matters for height-based safety targets; (c) nominal model
  ignores the per-env DR'd `mjx_model`; (d) gradients through 4 contact-rich `mjx.step`s: cost (one jacrev per env
  per step) and NaN/zero gradients at contacts; (e) the obs->state mapping assumes the observation layout of that
  branch (check `dynamics_observation_indices` still matches after the obstacle/scan obs additions).
- Estimate: SafeFall ~0.5 day incl. test; version (i) ~2 days incl. a test that the MJX one-step prediction matches
  `env.step` without DR/noise (that test also answers risk a/b).
