### State x (plan 4.2 scheme 1), S = 51
`joint_pos[0:12]` rad (absolute) · `joint_vel[12:24]` · `imu_ang_vel[24:27]` (gyro, IMU frame) · `projected_gravity[27:30]` ·
`last_action[30:42]` (chosen, undelayed u_{t-1}) · `base_lin_vel[42:45]` (qvel[0:3] in the IMU frame) · `imu_height[45]` ·
`roll_pitch[46:48]` · `base_xy[48:50]` (world) · `base_yaw[50]` (world). Window-start frame: `window_origin` + `to_window_frame`.

The IMU groups are read exactly where the env reads them for its observation and termination (`site_xmat`,
`site_xpos`, gyro `sensordata`). MuJoCo computes those at the start of the last physics substep. The shock / DR step
changes qpos / qvel without recomputing them, so x^- and x^+ of one step differ only in joint_pos, joint_vel,
base_lin_vel and base_xy. At an episode start the env skips `mjx.forward`, so the first state of an episode has
stale IMU groups. The world model has to mask transitions with `episode_step == 0`.

### xi, X = 507 (37 groups)
Every model field and internal-state parameter changed by the DR functions (seen / unseen robot, MuJoCo model,
joint dropout, action delay, PD offsets / scaling, curriculum coefficient, nominal IMU height, ground height). It is
recorded per step: `xi_idx[t]` gives the parameters of the physics of step t, and `xi_next_idx[t]` the parameters
after the DR step (before any reset). Both index a deduplicated `xi_table`.

### Delay (plan 4.3)
`delay_step(buffer[..., M+1, A], u, delay_steps) -> (u~, buffer')` is bit-exact with `DefaultActionDelay` given the
realized delay. The env's delay is 0 except when the DR draw is "mixed" (5 %), then U{0, 1} per step.
`delay_steps_from_xi(xi, key=None)` gives the fixed delay, or for mixed envs a random draw (with key) or the worst case 1.

### o(x)
`make_policy_obs_fn(env)` returns `obs_fn(x, command, xi)`, which gives the 45-dim policy obs, and `full_obs_fn`,
which gives the 104-dim vector for `policy.apply`. It equals the env's noise-free observation within 2e-6 on every
recorded step (test). Nothing is missing. Limitation: it only covers the plain locomotion observation and raises for
ball-plate / obstacle / exteroception blocks.

### Margins (plan 4.5)
`margin_fall(x, xi, margin_config_from_env(env))` = min(height term, qvel term[, tilt term if `use_tilt`]):
- height term: imu_height − (1−c)·0.8·h_nom (paper / T06b formula, c = curriculum coefficient from xi)
- qvel term: 100 − 1e-3 − max|qvel[0:3]| (the env's qvel-limit termination)
- tilt term is off in T06b

Tests: `margin < 0` ⟺ env `terminated` on every recorded step, at eval (c = 1) and in train mode (c = 0). The
height term alone ⟺ `constraint/terminated`.

`margin_fall_physical(x, xi, PhysicalFallConfig)`: imu_height < 0.5·h_nom or tilt > 1 rad. This is a physical fall
event, not a termination; T14 can report both.

### Finding: what "failure" means in T06b (and in the paper code)
With `height_curriculum_scaled=True` the threshold is (1 − c)·0.8·h_nom. At eval c = 1, so the threshold is 0 and a
termination means **the IMU went below the ground**: the robot is on its back or side, with the trunk on the floor.
The other possible cause is the qvel limit. The paper code at `cacffe7` is identical:
- `ncbf_mujoco/robot_locomotion/{mjx,mujoco}/termination_functions/below_height.py` uses the same (1 − c) formula
  with `height_percentage_threshold` 0.8, and has no tilt term.
- Both envs set `env_curriculum_coeff = 1` in eval mode (mjx `environment.py:282, 356`; CPU mujoco `:185-190, 392`;
  the CPU `test()` hard-codes `eval_mode = True`).
- Termination = below_height | any(|qvel[:3]| == 100).
- During training the threshold also drops to 0 once the curriculum reaches 1, so the critic's labels
  (`termination_window`) are "IMU below ground" for most of training as well.

The data (section 3) quantifies how often the robot is physically fallen without terminating.

Reading the oracle columns:
- The oracle (no shocks, no noise, noise-free observations) agrees with the actual outcome almost perfectly up to
  H=10. That means a failure within 10 steps is already decided by the physical state.
- At H=50 under heavy perturbation, agreement drops to 0.90-0.94. Under noise the actual trajectory fails more often
  than the oracle (noise after t causes the extra failures). Under pushes both fail about equally often, but on
  different (t, env).

### Termination causes and physical falls (coordinator's questions 1-3)
1. **Cause**: 243,591 / 243,591 terminations are "IMU height < (1-c)·0.8·h_nom = 0". qvel limit 0, other 0 — in every
   method x setting cell (table above, `termination_causes` in each `summary.json`).
2. **Physical fall without termination** (`margin_fall_physical`: IMU height < 0.5·h_nom or tilt > 1 rad;
   `experiments/pncbf/T12/t12_fallstats.py`):
   - Every termination is preceded by a physical fall in the same episode: 0 terminations without a prior fall.
     The fall comes a median 11 steps (0.22 s) before the termination (p90 26 steps, max 967).
   - 9,729 of 396,908 episodes (2.5 %) have a physical fall but never terminate: the robot recovers, or the episode
     is truncated / cut by the window end.
   - Only **391 episodes** (0.1 %) stay fallen for ≥ 0.5 s (25 consecutive steps) without terminating; 141 of those
     run into the time limit. Per cell: 10-57 such episodes, against 10,851 ≥0.5 s falls that do terminate.
   - So for these policies the IMU-below-ground termination is a slightly delayed (≈0.2 s) proxy of a physical fall.
     A world model that predicts the termination must predict ~0.2 s further into the fall. `margin_fall_physical`
     gives T14 the earlier event.
3. **Paper code `cacffe7`**: same rule (section 1). Its eval threshold is also 0 (c = 1), it has no tilt term, and
   it has the same qvel term. The T06b failures therefore mean the same thing as the paper's.
