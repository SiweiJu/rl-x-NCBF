## 1. Differences that can affect a shield-off PPO policy

Method: diffed cacffe7 (`ncbf-q`) against pncbf-v2 @ aa6e29f:
- `flax_full_jit/{ppo,policy,critic,ncbf,default_config}.py`;
- the whole MJX env (`environment.py`, all reward / command / sampling / termination / DR / terrain functions,
  env `default_config.py`) and the Go2 robot config.

The T06b PPO run is `t06.sbatch METHOD=ppo`: shield off, critic still trained.

### New switches (this task; default = v2 behavior)
All are in `rl_x/algorithms/ncbf_ppo/flax_full_jit/paper_compat.py`.

| switch | v2 default | paper (cacffe7) | where |
|---|---|---|---|
| `algorithm.policy_layer_norm` | False | **True**: Dense(512) → LayerNorm → elu → 256 → 128 | policy.py |
| `algorithm.value_layer_norm` | False | **True**, same layout | critic.py |
| `algorithm.gae_stop_at_truncation` | True: recursion × (1 − dones) | **False**: × (1 − terminations), so the advantage of the next episode leaks into the last ~10–20 steps before a time-out (γλ = 0.891). δ bootstraps with (1 − terminations) in both. | ppo.py → `gae_advantages` |
| `algorithm.policy_logstd_clip` | True: clip log σ to [−5, 2] | **False**: no clip | ppo.py (rollout, loss, initial KL, metric) |
| `algorithm.ncbf.anticipation_style` | `mean_action`: shield(μ), sum over action dims | **`sampled_action`**: shield(a_sampled), mean over dims | ppo.py → `anticipation_squared_error` |

The anticipation row matters only with the shield off:
- v2's anticipation loss is then exactly 0;
- the paper's is `0.01 · 0.5 · mean((μ − a)²)`, a weak pull of μ toward the rollout actions.

With the shield on, the paper also used the post-step h_prev (the F1 issue), which this switch does not reproduce.

Checkpoints: `PPO.load` copies top-level algorithm keys from the checkpoint config, so the switches are restored on
load and eval. Old checkpoints have no LayerNorm parameters and keep loading with the defaults (tested).

### Differences without a switch, and why not
| difference | why no switch / no run |
|---|---|
| `target_kl` gating | Already switchable; T06b uses `target_kl=0` (paper: none). |
| in-training eval with the shield (β = 1) | Eval only logs; with `use_safety_layer=False` the dummy shield returns the raw action, so it equals the paper's eval. It cannot affect training. |
| history encoder / latent in the policy input | `use_history_latent_for_policy/value`, `use_decoder_output_for_policy` = False in T06b, so the policy and value nets see exactly the paper's index sets. Diffed: `policy_observation_indices` and `critic_observation_indices` are unchanged. The encoder/decoder/NCBF are trained on their own optimizers, so they never touch the policy parameters. |
| policy / value optimizers | Same: separate Adam per net, clip 5 each, same linear LR anneal. Diffed. |
| PPO loss | pg / clip / value loss / per-minibatch advantage normalization / entropy (coef 0) are equivalent. Diffed. |
| paper NCBF pretraining | 2 extra env steps + 5 critic updates before training. Negligible; the critic does not act on the policy. |
| RNG streams | 5-way vs 7-way/8-way splits in the env and per-minibatch splits in PPO. Not a systematic effect; 3 seeds per variant. |
| env reward (`default.py`) | Only new info metrics (`reward/*_total`) and an unused `all_feet_off_ground_coeff`; the reward formula is identical. |
| env termination | The `height_curriculum_scaled` and `body_tilt_threshold` switches are set to the paper values in T06b. The qvel-limit termination is identical. |
| env command | The `velocity_ratio` switch is (1, 1, 1) in T06b. The command is not resampled at reset in either code (`step_probability` → setup False). Ranges, zero chances and p = 0.002 are identical. |
| env obs | Identical policy/value inputs. v2 appends 2 safety bits (not in any policy/value index set). The qpos/qvel blocks drop unactuated joints (none on Go2). Normalization is identical. |
| env DR / pushes / noise / terrain / Go2 model | The diffs add only booster/ball/obstacle code paths. The paper's `create_env` read the Go2 config from `custom_mujoco`, which is byte-identical to `ncbf_mujoco`'s. |
| env reset / step bookkeeping | Functional rewrite (dict copies instead of in-place updates) with the same values. `episode_total_xy_velocity_diff_abs` is now `=` instead of `+=` but is never read. |
| resume (scavenger requeue) | Restores params, optimizer, counters and the env curriculum. It re-resets all envs. Not a training-signal change. |

### Evidence that the two "minor" switches are inert for PPO
Final checkpoints (read on IAS, `policy_logstd`):
- T05 PPO: σ = 0.050 (min 0.045).
- T06b PPO: σ = 0.042 (min 0.037).

So log σ ≈ −3.1, far from the −5 clip.

The paper anticipation gradient on μ is 0.01/12 · (μ − a). The PG term's gradient is A · (a − μ)/σ², i.e. about 400 · A · (a − μ)
at σ = 0.05. The ratio is about 10⁻⁶. Both switches are therefore kept in variant (b) but get no leave-one-out run in the
default sweep (optional variant `b-no-minor`, array 15–17).

Notable as a side effect: T06b policies end with a ~15 % smaller σ than T05, all 5 seeds, both sets with tight spread.

## 2. Bisect design
Go2 flat PPO-only = the T06b `ppo` config (`t06.sbatch METHOD=ppo`: shield off, critic still trained, same args, neg
buffer 5). Seeds 1042 1142 1242 are the first three seeds of T05 and T06b PPO, so the seeds are matched. Each run is
1e9 steps with `runner.resume=True`. Script: `experiments/pncbf/T06c/t06c.sbatch`; array index i → variant i/3, seed i%3.

| idx | variant | switches |
|---|---|---|
| 0–2 | `a` | none (= T06b ppo on the new tree: also a control for the code version) |
| 3–5 | `b` | all paper values: LN policy + LN value + GAE at terminations + no log σ clip + paper anticipation |
| 6–8 | `b-no-lnpol` | b without policy LayerNorm |
| 9–11 | `b-no-lnval` | b without value LayerNorm |
| 12–14 | `b-no-gae` | b with GAE cut at truncations |
| (15–17) | `b-no-minor` | optional: b with the log σ clip + v2 anticipation |

**Leave-one-out from (b) rather than add-one-in from (a).** Both need one variant per switch (3 here, since the minor pair
is inert), so neither needs fewer runs. Leave-one-out is more informative for the same cost:
- Policy LayerNorm and value LayerNorm are one change in the paper and may only work together. Add-one-in would then show
  two "no effect" results; leave-one-out shows both as necessary.
- (b) is the anchor of every comparison. If (b) reaches T05 on the v2 eval, it also rules out an eval artifact (the T05
  numbers come from the paper tree's eval).

If (b) does **not** close the gap, the leave-one-out runs are uninformative. The cause is then outside these switches,
and the next steps are:
- cross-evaluate T05 PPO policies in the v2 eval: the paper policy's parameter tree loads into the switched v2 policy,
  see `test_layer_norm_switch_gives_the_paper_networks`;
- revisit RNG and seed variance.

Cost: 15 runs × ~8.3 h on a 3090 (T06b: 3.9 s/update, 7524 updates = 986 M steps).

Eval: G0 part 2 protocol, mode A.
- `experiments/pncbf/eval/g0_part2_groups_t06c.json` adds groups `T06c-<variant>` with T06b's env args. The out dir is
  the same `/home/ju/repo/pncbf/g0_part2/out`, so T05/T06b are reused.
- `experiments/pncbf/eval/t06c_compare.py` writes the metric table: per seed, the mean success over the 22 points, then
  mean ± se over seeds, with Δ vs T05 and T06b (all 5 seeds and the matched 3) and the "gap closed" fraction.
