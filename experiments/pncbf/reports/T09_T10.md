## 1. What was built

New algorithm **`p3o.flax_full_jit`**. It copies the structure of `ppo_lagrangian.flax_full_jit` (T07):
- the same full-jit rollout scan, reward and cost GAE, epoch × minibatch scan, eval and orbax checkpoint;
- the same cost, `info["constraint/cost"]`: 1 on the fall step, plus a collision when collisions terminate;
- the same `lagrange.measure_cost`, so `cost_measure` is `episode` (default, as T08) or `rollout`;
- the same networks: `ppo.flax_full_jit` policy (512-**LayerNorm**-256-128, ELU, state-independent log σ) and critics (512-LN-256-128). The reward and cost critics have separate Adam optimizers. lr, clip and max-grad-norm match PPO-Lag.

PPO-Lag has no LayerNorm switch: its policy always has the LayerNorm, which matches the v2 default `policy_layer_norm=True`.

### P3O loss (paper eqs. 5–7)

```
L = E[-min(r Â_R, clip(r) Â_R)] + κ · relu( E[max(r Ã_C, clip(r) Ã_C)] + offset~ ) + critic losses
```
- The relu is taken of the **minibatch mean**, as in the paper and OmniSafe. So the loss is computed batched, without per-sample vmap.
- The cost surrogate takes the max. A cost decrease beyond the trust region earns nothing; a cost increase always counts.

Switches (defaults first):
- `p3o.kappa = 20`: the paper's value for all tasks (supplement table) and OmniSafe `P3O.yaml`.
- `p3o.clip_cost_surrogate = True`: paper eq. 7. `False` gives OmniSafe `p3o.py` (`ratio * adv_c`, unclipped).
- `p3o.constraint_normalization = per_step`: offset = (J_c − d)/T, with T the mean episode length from the same rollout (CPO's estimator).
  - Why: the paper writes (1−γ)(J_C − d) for a *discounted* J_C. Our J_c is failures per episode, and Δ J_ep ≈ T·Δ E_t[r A_C] (the T07 CPO argument).
  - Alternatives: `one_minus_gamma` (paper formula, literal) and `none` (OmniSafe: `EpCost − cost_limit`).
- `p3o.cost_advantage_normalization = scaled`: per minibatch, Ã = (A − μ)/σ and offset~ = offset/σ.
  - At π = π_k the relu argument is then exactly offset/σ, so **the penalty is on iff J_c > d**.
  - Options:
    - `consistent`: N-P3O, Lee et al. 2023 (arXiv 2309.15430) eq. 16, offset~ = (offset + μ)/σ;
    - `standardize`: the P3O paper's normalization trick, offset unscaled;
    - `center`: the OmniSafe buffer;
    - `none`.
- `p3o.enabled = True`. `False` gives the plain PPO policy loss; the cost critic is still trained.

**Why `scaled` and not N-P3O's `consistent` (deviation, found in the smoke):**
- With `consistent` (job 183780), μ = the mean cost-GAE advantage is critic bias. E_{π_k}[A^{π_k}] = 0 by definition.
- That bias was negative enough to switch the penalty off: `p3o/penalty_active` mean 0.65, 0 at the end, while J_c = 0.98 ≫ d = 0.01.
- With `scaled` (job 183792) the penalty was active in 20/20 updates.
- `standardize` leaves offset ≈ 1e-4 against a unit-variance surrogate, so feasibility hardly matters. That is a units mismatch.

References followed:
- Zhang et al. (IJCAI 2022) eqs. 5–7, κ = 20, Theorem 1 (exact penalty for κ ≥ ‖λ*‖∞).
- OmniSafe `omnisafe/algorithms/on_policy/penalty_function/p3o.py` (`_loss_pi_cost`, `_update_actor`: one joint actor loss and one optimizer step) and `configs/on-policy/P3O.yaml` (κ = 20, cost-advantage centering). Read from GitHub main on 2026-10-27.
- Lee et al. 2023 for the normalized variant.
- PPO hyperparameters are the repo's paper-scale PPO, not OmniSafe's, for parity with PPO-Lag and CPO in T08.

### CaT (`algorithm.cat.*`, default off)

- `cat.enabled = False`, `cat.constraint_source = collision`. Sources:
  - `collision`: `env_info/obstacle_collision`, binary;
  - `penetration`: max(0, −`env_info/obstacle_min_clearance`), in m;
  - `cost`: `constraint/cost`.
- `cat.p_max = 1.0` (hard constraint, as the paper's contacts), `cat.min_p = 0`, `cat.tau = 0.95`, `cat.clip_reward_at_zero = True`.

Applied after the rollout, before the reward GAE:
- δ = min_p + clip(c⁺/c_max, 0, 1)(p_max − min_p) on violating steps, 0 otherwise;
- c_max = EMA (τ) of the per-step max over envs, initialized to the first step's max, clamped ≥ 1e-6;
- reward ← clip(r(1 − δ), 0);
- reward-GAE termination ← max(terminated, δ). So the bootstrap and the GAE trace are scaled by (1 − δ).
- The env is **not** reset by δ (paper: "terminations are not environment resets").
- The cost GAE and J_c use the real terminations.

This follows paper eq. 6 and Alg. 1, and the reference code `gepetto/constraints-as-terminations`, `exts/cat_envs/.../utils/cat/{constraint_manager.py, cat_env.py}`:
- τ = 0.95 and the per-step EMA come from the reference code; the paper gives no τ;
- so do min_p and the reward clip at 0.

Two deviations:
- The reference also sets done = 1 at time-outs. The repo's PPO GAE never cuts at truncations, so neither does CaT here, for parity.
- The brief's formula clip(c/c_max, 0, p_max) is replaced by the paper's p_max·clip(c/c_max, 0, 1). They are identical for p_max = 1.

**Env hook: none.** PPO + CaT = `--algorithm.name=p3o.flax_full_jit --algorithm.p3o.enabled=False --algorithm.cat.enabled=True`, with the existing env switch `--environment.obstacles.terminate_on_collision=False`.
- Without that switch every collision is already a hard termination. In training mode the algorithm refuses to start in that case (ValueError).
- In test mode it does not refuse, so evals can run with collision terminations.
- Falls stay real terminations (plan: CaT only matters for collisions).

`run_baseline.sh` gained `METHOD=p3o` (`KAPPA`) and `METHOD=ppo_cat` (`CAT_SOURCE`, `CAT_P_MAX`; it sets `OBSTACLES_TERMINATE_ON_COLLISION=False` unless given).
- Moving obstacles through `OBSTACLES_ENABLED` / `OBSTACLES_*` / `OBSTACLES_PRESET` (sources `cluster_runner/obstacle_args.sh`).
- Tags `phase/$PHASE, task/$TASK, exp/$TASK`.
- `PYTHONPATH` is now set, not prepended (brief).
- Old METHODs behave as before. Their tags gain only `exp/T08`.

## 2. Tests

`JAX_PLATFORMS=cpu .venv/bin/python -m pytest tests/test_p3o.py -q` → **14 passed** in 4 min 54 s (env construction dominates).

- The penalty is κ·relu(offset) at r = 1. It is zero, with zero gradient, while feasible. When violated it grows with slope κ and its gradient is κ·∇surrogate. Checked with and without clipping.
- Cost-surrogate clipping:
  - equals max(rA, clip(r)A) and equals −PPO-clip(−A);
  - the gradient w.r.t. r is 0 exactly for (A > 0, r < 1−ε) and (A < 0, r > 1+ε), and A elsewhere.
- Offset units: per_step, one_minus_gamma, none.
- Normalization modes:
  - `consistent` = the unnormalized argument / σ;
  - `scaled` turns on iff offset > 0 even with a strongly biased μ, while `consistent` turns off in that case;
  - `center` / `standardize` give the expected moments.
- End-to-end on Go2 (16 envs, 2 updates), all metrics finite:
  - default P3O; in every update, `penalty_active_at_start` == (J_c > d);
  - OmniSafe-style P3O (rollout measure, center, none, unclipped);
  - `p3o.enabled=False` (penalty loss exactly 0).
- Save → `P3O.load` → 1-point mode-A eval sweep, as T08:
  - params are restored;
  - the nested `p3o.kappa` comes back from the checkpoint while an explicitly set key (`cost_limit`) is kept;
  - `eval_summary.json` has `algorithm = p3o.flax_full_jit`, mode A.
- CaT unit tests:
  - binary collision → δ = p_max; reward and termination scaling; the reward clip at 0 and its switch;
  - graded violation and the EMA running max; rollout scan == per-step calls.
- CaT on the **real obstacle env** (obstacles spawned 0.2 m from the base, `terminate_on_collision=False`):
  - collisions happen with clearance < 0, carry no cost and do not terminate;
  - δ == collision, CaT reward = 0 on collision steps, effective termination = 1;
  - penetration gives δ ∈ (0, 1] only on collisions.
- PPO + CaT training on that env (16 envs, 2 updates): finite, violation rate > 0, δ | violation = 1, reward scale < 1.
- `terminate_on_collision=True` with CaT on → ValueError.

## 5. Open points

1. **Memory for the CaT run.** Obstacle jobs peak at 9.5 GB of 10 GB. 5G per CPU passed the smoke, but `MEM_PER_CPU=8G` would be safer for the 1e9 run. The brief reserves 8G for NCBF/buffer jobs, so this is the main session's call.
2. **κ = 20 is cost-dominant.** With the per-step offset our J_c (0.04–0.07 in T08) stays above d = 0.01 for the whole run. The cost term, weighted 20 against a reward term of weight 1, is then on almost always, and the policy grad norm rises from 0.3 (PPO-Lag) to 6–8, so max-grad-norm 5 clips it. If the sanity runs learn too slowly, κ ∈ {1, 5} is the first tuning knob; N-P3O used κ = 1.
3. CaT with binary collisions and p_max = 1 is a hard "future-reward termination". The `penetration` source with p_max < 1 is the graded alternative from the paper's soft constraints; it is not tested at scale.
4. The P3O sanity runs use the T08 env, not T06b's (§4). Say if P2 baselines should move to T06b instead.
