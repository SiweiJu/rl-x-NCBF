## 2. What was implemented

- `rl_x/algorithms/ncbf_ppo/flax_full_jit/eval_sweep.py` (new): `run_eval_sweep(model)`, called from `PPO.test()` when
  `algorithm.eval_sweep.enabled=True` (default False; training and the old `test()` unchanged; `load()` never takes `eval_sweep`
  from the checkpoint config). One process = one checkpoint x terrain x mode, all perturbations x probabilities x eval seeds inside.
  - 1 episode per env, exactly `horizon` steps, later auto-reset episodes ignored; success = not terminated.
  - action noise: per env/step Bernoulli(p), N(0, std²) per joint, `noise_std_mode=absolute|action_range_fraction`,
    `noise_point=pre_shield|post_shield`.
  - push: `push_impl=env` (default) uses the env's own push at probability p with trunk bound x `push_scale` (python constants,
    `jax.clear_caches()` + retrace per push point, about 30 s compile); `push_impl=eval_loop` applies the same perturbation function
    before each env step with traced p/scale (one compile, 1-step sensing delay vs. env pushes, push events counted).
    `background_push_prob` (default: env config 0.002) during the action-noise setting.
  - mode A: raw policy action, the shield is never traced; mode B: shield (needs `ncbf.use_safety_layer=True`).
  - paired eval: reset/DR, noise and push draws come from `PRNGKey(eval_seed)` only, independent of the policy; draws are nested in p.
  - agents: `MultistepAgent` (pncbf-v2, mirrors `_policy_and_shield`; test asserts equality) and `PaperAgent` (ncbf-q networks/shield).
- Output per point: `<out>/<label>/<perturbation>_<terrain>/mode_<A|B>/sp_<p>/seed_<s>/eval_summary.json` + `eval_episodes.npz`
  (per-env return/length/flags for paired tests). Summary = old multistep fields (`failure_rate`, `mean_episode_return`,
  `intervention_rate`, `mean_delta_u`, ...) + `schema`, `success_rate(_se)`, `mean_episode_return_se`, `survival_rate_at_threshold`
  (paper's >=250-step criterion), `event_rates` (termination, fall, qvel_limit, obstacle_collision, unsafe_<head>),
  `intervention_rate_se`, `mean_delta_u_when_active`, noise/push events, full `protocol`, sweep metadata, `git_commit`, `rl_x_path`,
  `wall_time_s`.
- `experiments/pncbf/eval/run_eval_sweep.py` (driver: checkpoints JSON x terrains x modes, `--list_jobs`, `--task_index`, `--dry_run`,
  every protocol value overridable), `protocol_default.json` (all values, TODO ones marked in this report), `eval_sweep.sbatch`
  (array task = job; exports `PYTHONPATH=<own checkout>` and prints `rl_x.__file__` + commit, because conda `rlx-ncbf` has `rl_x`
  installed editable from `/home/ju/repo/rl-x-NCBF`; the driver also forces it per job).
- `experiments/ncbf_tools/collect_eval_summaries.py`: reused, adds a `path` column.
- `misc/rss/eval_summary_reader.py` (summaries -> rows/DataFrame with the paper aliases `experiment`, `entry_name`, `finished_rate`,
  `avg_return`; mean over eval seeds, then mean ± SE over checkpoints) and `misc/rss/plot_fig2_from_eval_summaries.py` (Fig. 2:
  2 x 4, success and return vs sampling prob, 4 settings, lines per method/mode). Note: `misc/rss/` is in `.gitignore`; files are
  force-added. pandas is not in the local venv (the reader's row loader works without it).

## 7. Reconciliation with the paper's CPU eval path (follow-up, 2026-10-22)

**Question:** recover's reconstructed CPU eval (`pncbf-v2-recover`: `paper_eval/paper_eval_sweep.sh`, non-jit `ncbf_ppo.flax`
`test()`, CPU MuJoCo, 1 env) gave ours-seed-42 10/10 at noise p=0 flat. The T04 MJX smoke gave 0.58.

### 7.1 Causes of the gap (in order of size)
1. **Wrong checkpoint in the smoke test.** The 0.58 came from `202601_paper/ncbf-q-safety/..._gc_5_h_25_seed_42`, a γ_c=5
   variant that is in no figure (INDEX.md). The Fig. 2 "ours" seed 42 is `ncbf-q-safe` 5wpajwko =
   `paper_models/ours/q-safe-H-gamma_0.405_seed_42_H_25.model`. On it, the unchanged MJX eval gives 0.98 (mode A, 64 envs) and
   0.93 (mode B, 256 envs) at p=0.
2. **The paper eval used a different shield than training.** `test()` calls the non-jit `ncbf_ppo/flax/ncbf.py`
   `make_get_safe_action_q`; training used `flax_full_jit/ncbf.py` `make_get_safe_action` (`ncbf-q` branch). The two differ in four ways:
   - CVaR over the lowest k=2 of 5 members (α=0.6) vs k=3 (α=0.4);
   - QP slack scaled by std(h(x))² vs clip(std(h(u)), 1, 10)²;
   - shield off while last_action == 0;
   - `test()` passes last_state = the *current* observation (`flax/ppo.py:1001-1002`), training passes the previous one.

   Under noise this matters a lot. At p=0.6, mode B, 256 envs, sampled commands, success over the full episode is
   **0.012 with the training shield vs 0.141 with the CPU-test shield**. New option `algorithm.eval_sweep.paper_shield=train|cpu_test`
   (`PaperAgent`, paper-code checkpoints only).
3. **Initial command.** Neither env resamples the velocity command at reset: it persists across episodes and is resampled with
   p=0.002 per step (the first reset sets it to 0). The CPU eval runs its episodes in sequence, so after the first one most
   episodes start with a random command. A batched MJX reset starts every env at 0, i.e. standing still.
   - The return depends on this. CPU returns: episode 1 25.7, episodes 2-100 mean 17.2.
   - MJX returns: 23.1 with all-zero starts vs **16.8** with sampled starts.
   - New option `eval_sweep.initial_command_zero_prob`. The default 1.0 keeps the env behavior. The protocol uses 0.16 (≈ paper: 10 sequential 10 s episodes per process).
4. Smaller: the observation at step 0 still shows the zero command when a command is sampled at reset (one step). MJX vs MuJoCo
   physics: the remaining difference is within sampling error, see 7.3.
